## Your manual steps

Estimate: 15 minutes total, one-time.

### Step 1 — Register on PyPI (5 min)

1. Create a PyPI account at https://pypi.org/account/register/ if you don't have one yet.
2. **Enable 2FA** (required for new accounts as of 2024). Authenticator app, not SMS.

### Step 2 — Reserve the `claude-recall` name (2 min)

Fastest path: do a one-time local upload of v0.4.3 to PyPI to claim the name. This gives you the `claude-recall` project page on PyPI before v0.5 auto-publishes.

```powershell
# From the repo root, with the .venv active
.venv\Scripts\activate

# Build fresh wheels locally
Remove-Item -Recurse -Force dist -ErrorAction SilentlyContinue
python -m build --wheel
python -m build --sdist

# Verify they're PyPI-ready
python -m twine check dist/*

# Upload to PyPI (prompts for username → use __token__; password → your PyPI token)
python -m twine upload dist/*
```

You'll need a PyPI API token for the upload (see Step 3 — create it first). Or, if you'd rather reserve the name via the PyPI web UI first, it's at https://pypi.org/manage/projects/ after registration (limited functionality — uploading a wheel is simpler).

**Alternative — skip this step.** The `publish-pypi` job in CI will auto-create the project on first successful upload. Only reason to reserve manually is to ensure the name is yours before anyone else claims it. Given `claude-recall` is specific enough, this is probably unnecessary.

### Step 3 — Generate a project-scoped API token (5 min)

1. https://pypi.org/manage/account/token/ → *Add API token*.
2. Token name: `claude-recall CI` (or anything memorable).
3. Scope: **start with "Entire account"** if the project doesn't exist on PyPI yet (you need it for the first upload, then switch). After the first upload, regenerate the token scoped to the `claude-recall` project only.
4. Copy the token (starts with `pypi-`). **Save it somewhere secure — PyPI shows it exactly once.**

### Step 4 — Add the token as a GitHub secret (3 min)

1. https://github.com/LearnedGeek/claude-recall/settings/secrets/actions
2. *New repository secret*.
3. Name: `PYPI_API_TOKEN` (exact; the workflow reads this name).
4. Value: paste the token from Step 3.
5. Save.

### Step 5 — Tag v0.5.0 (1 min) — when ready

After Steps 1-4 are complete, tell the helper / next session to proceed with v0.5.0 release. The tag push will fire the `publish-pypi` job and upload both wheels to PyPI.

Or self-serve:

```powershell
git pull
# Version bump and CHANGELOG are already drafted in the v0.5 branch/commits
# when the helper runs the release; for now, just tag once ready:
git tag -a v0.5.0 -m "v0.5.0 — PyPI publish"
git push origin v0.5.0
```

CI will then:
- Build both wheels (existing behavior)
- Attach them to the GitHub Release (existing behavior)
- **Upload them to PyPI** (new in v0.5)

After ~5 minutes, `pip install claude-recall` works globally.

## Optional hardening

### Trusted Publishing (recommended after first successful upload)

Switch from API-token auth to OIDC-based Trusted Publishing. Eliminates the stored secret entirely; GitHub Actions identity is verified by PyPI directly.

1. https://pypi.org/manage/project/claude-recall/settings/publishing/
2. *Add a new pending publisher*:
   - Owner: `LearnedGeek`
   - Repository name: `claude-recall`
   - Workflow filename: `build-wheels.yml`
   - Environment name: `pypi` (matches the workflow's `environment: name: pypi`)
3. Remove the `password:` line from the `publish-pypi` step in `build-wheels.yml` (OIDC makes it unnecessary).
4. Delete the `PYPI_API_TOKEN` secret from GitHub.

Cleaner long-term, but takes 10 extra minutes and isn't needed for the first release.

### GitHub Environment gate (optional approval step)

The workflow references `environment: name: pypi`. By default GitHub treats this as "auto-create, no gate." If you'd rather manually approve each PyPI publish:

1. https://github.com/LearnedGeek/claude-recall/settings/environments
2. Create environment named `pypi`.
3. Add a required reviewer (yourself). Now every tag push pauses at the `publish-pypi` job waiting for your click.

Useful if you want a human in the loop for production pushes; skip otherwise.

## Troubleshooting

**"File already exists" on upload:** PyPI rejects overwrites. If a previous tag-push attempt partial-uploaded, bump the patch version. `skip-existing: true` is set in the workflow so partial conflicts within a single release don't fail.

**Wheel platform tag rejected:** PyPI is strict about platform tags. `py3-none-win_amd64` and `py3-none-any` are both valid. If you see "invalid wheel filename" errors, check that the rename step in `build-wheel-win-x64` ran correctly.

**"Invalid or non-existent authentication information":** The `PYPI_API_TOKEN` secret is either missing or has been revoked. Re-check Step 3 + Step 4.

**"Project-URL" rendering issues on PyPI:** The polished `pyproject.toml` has been verified locally via `twine check`. If something looks off on the live page after first upload, edit and re-push — PyPI re-renders README on every upload.
